Why your SQL Server report doesn't match the source system

When a report and an ERP screen disagree, the gap may come from timing, filters, or how records are combined. Start with a small, repeatable comparison before changing data or rewriting the report.

1. Agree on what the number represents

Write down the metric, date range, time zone, business unit, status filters, and whether the report includes reversals or adjustments. Confirm whether each source uses transaction date, posting date, or another date. Two correct reports can disagree when they answer different questions.

2. Compare the same point in time

Check when each system refreshes and whether either includes unposted or in-flight changes. Record the refresh times and compare the same period. SQL Server isolation settings also affect what a query can see; work with the database owner before changing them. See Microsoft's transaction isolation documentation.

3. Narrow the discrepancy

Compare totals by day, location, status, or another relevant dimension, then inspect a small set of mismatched record identifiers. Check whether records are missing, duplicated in the result, excluded by a filter, or assigned to a different period. Use approved access and avoid sharing customer records in public examples.

4. Inspect joins and calculations

A one-to-many join can repeat a source amount in the result. Compare row counts and totals before and after each join, and confirm the intended level of detail. Check null handling, rounding, unit conversions, and whether calculations are performed before or after aggregation. A distinct count or a removed duplicate is not automatically a fix; first establish what each row is meant to represent. Microsoft's COUNT reference explains how different count expressions treat rows and null values.

5. Document and validate the fix

Keep a reproducible example with expected totals, record the agreed business rule, and test both the discrepancy and unaffected cases. Coordinate changes with the system owner, use an appropriate test environment, and agree on a handoff so the next person can repeat the checks.
